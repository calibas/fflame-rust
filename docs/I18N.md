# Internationalization (i18n) Guide

## Overview

The Fractal Flame Renderer uses `rust-i18n` for internationalization support. Translation files are stored as YAML files in the `locales/` directory.

## Current Status

- **Implemented**: Infrastructure and English translations
- **Available Languages**: English (en) only
- **Total Strings**: 200+ UI strings translated

## Architecture

### Dependencies

```toml
[dependencies]
rust-i18n = "3.1"
```

### Module Structure

- `src/i18n.rs` - Core i18n module with locale management
- `locales/en.yml` - English translation file (default)
- `locales/[lang].yml` - Future language files

### Font Support

**Current**: egui default font
- ✅ Full support: Latin scripts (English, Spanish, French, German, Polish, etc.)
- ✅ Full support: Cyrillic (Russian, Ukrainian)
- ✅ Full support: Greek
- ⚠️ Limited support: CJK (Chinese, Japanese, Korean) - basic characters only
- ❌ No support: Arabic/Hebrew (RTL languages)

**For full CJK support**, add Noto Sans CJK or similar comprehensive fonts via egui FontDefinitions.

## Usage

### In Rust Code

```rust
use fractal_flame_wgpu::i18n;
use rust_i18n::t;

// Simple translation
let title = t!("app.title");

// With variables
let message = t!("messages.welcome", name = "Alice");

// Change language
i18n::set_locale("es");

// Get current language
let current = i18n::current_locale();

// Get supported locales
let locales = i18n::supported_locales();
```

### Translation File Format

YAML format with nested keys:

```yaml
en:
  app:
    title: "Fractal Flame Renderer"
  menu:
    file: "File"
    edit: "Edit"
  panels:
    transforms: "Transforms"
    colors: "Colors"
```

### UI Integration

Language selector is in Settings panel → Preferences section:
- Shows native language names
- Changes apply immediately (no restart required)
- Persists via `set_locale()`

## Adding a New Language

1. **Create translation file**: `locales/[lang].yml`
   - Copy `locales/en.yml` as template
   - Translate all strings (keep keys identical)

2. **Update supported locales** in `src/i18n.rs`:
   ```rust
   pub fn supported_locales() -> Vec<LocaleInfo> {
       vec![
           LocaleInfo::new("en", "English", "English"),
           LocaleInfo::new("es", "Spanish", "Español"),  // Add new language
       ]
   }
   ```

3. **Test** the translation:
   - Run app: `cargo run --release`
   - Open Settings → Preferences
   - Select new language from dropdown

4. **Add fonts** (if needed for CJK/RTL):
   - Add font file to `assets/fonts/`
   - Configure in `src/ui/mod.rs` `EguiLayer::new()`:
     ```rust
     let mut fonts = egui::FontDefinitions::default();
     fonts.font_data.insert(
         "noto_sans_cjk".to_owned(),
         egui::FontData::from_static(include_bytes!("../assets/fonts/NotoSansCJK.ttf"))
     );
     ctx.set_fonts(fonts);
     ```

## Testing Translations

### Manual Testing
1. Change language in Settings → Preferences
2. Check all panels for correct translations
3. Verify no missing keys (shows key name if missing)
4. Test special characters display correctly

### Unit Tests
```bash
cargo test --lib i18n
```

Tests verify:
- Default locale is "en"
- Supported locales list is populated
- Translation infrastructure works

## Performance Notes

- **No runtime overhead**: Translations compiled into binary via macro
- **No file I/O**: YAML parsed at compile time
- **WASM compatible**: All translations embedded in .wasm file
- **Zero allocations**: Static strings returned by `t!()` macro

## Known Limitations

1. **No dynamic pluralization**: English-centric string format
   - Use separate keys for singular/plural if needed
   - Example: `iterations.one` vs `iterations.many`

2. **No gender support**: Not needed for technical UI
   - Most strings are gender-neutral
   - Avoid gendered language in source strings

3. **No RTL support yet**: Requires egui layout changes
   - egui has some RTL support
   - Would need testing and adjustments

4. **CJK font required**: Default font has limited coverage
   - Works for UI, but may look poor
   - Add proper CJK font for production

## Contributing Translations

If you'd like to contribute a translation:

1. Copy `locales/en.yml` to `locales/[lang].yml`
2. Translate all values (keep keys unchanged)
3. Test in app to ensure display is correct
4. Submit pull request with translation file

Translation quality guidelines:
- Use formal/professional tone for technical terms
- Keep strings concise (UI space is limited)
- Match original meaning, not literal translation
- Test with actual UI to ensure it fits
