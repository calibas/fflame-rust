# Internationalization (i18n)

Every UI label is a key looked up at run time in a YAML translation file.
The app uses [rust-i18n](https://crates.io/crates/rust-i18n) 3.1:
`i18n!("locales", fallback = "en")` in [src/lib.rs](../../src/lib.rs)
compiles every `locales/*.yml` into the binary, on desktop and on the
web, so there is no file I/O at run time and a change to a locale file
needs a rebuild.

- Helpers: [src/i18n.rs](../../src/i18n.rs) — `current_locale()`,
  `set_locale(code)`, `supported_locales()`, and the locale tests.
- The picker: the globe menu in [src/ui/menu_bar.rs](../../src/ui/menu_bar.rs).
- Fonts: [src/ui/font_loader.rs](../../src/ui/font_loader.rs).

**See also:** [UI.md](UI.md). Design record:
[i18n-ui-migration.md](../archive/i18n-ui-migration.md).

## Locales

| Code | Language | File | Leaf keys | Of which English has |
|---|---|---|---|---|
| `en` | English | `locales/en.yml` | 2,351 | the reference, and the fallback |
| `es` | Spanish | `locales/es.yml` | 214 | 162 |
| `ja` | Japanese | `locales/ja.yml` | 204 | 84 |
| `zh-CN` | Chinese (Simplified) | `locales/zh-CN.yml` | 204 | 84 |

(Counts are leaf keys, not counting `_version`.) The three translations
cover a small part of the UI; any key a locale lacks is drawn in
English. They also carry keys English no longer has — 52 in Spanish,
120 in Japanese and Chinese — left from earlier versions of the UI: for
example `menu.fractal`, from before the Fractal menu became **Mode**.
None of them translates `menu.mode`, so that menu reads "Mode" in every
language.

## File layout

```yaml
_version: 1
# Application
app:
  title: "Fractal Flame Renderer"

menu:
  file: "File"
  mode: "Mode"
```

- `_version: 1` is rust-i18n's one-locale-per-file format: the file
  name is the locale code, and there is no language key at the top.
- Keys nest by group and are looked up with a dotted path:
  `t!("menu.file")`.
- English has 49 top-level groups, roughly one per panel or subsystem
  (`app`, `visibility`, `mode`, `menu`, `help`, `panels`, `transform`,
  `variations`, `color`, `palette`, `view`, `tonemap`, `history`,
  `palette_editor`, `palette_library`, `browser`, `fractal_gallery`,
  `escape_panel`, `sim_panel`, `textures_panel`, `progress`, and so on).
  The translations use 17 of them.
- Parameters are written `%{name}` in the text and passed by name:
  `t!("fractal_gallery.rendering", name = config_name)`.

## Choosing a language

The **globe (🌐) menu** at the right of the menu bar, shown when the
window is at least 500 points wide. The compact layout has no language
picker.

- Its rows come from `supported_locales()` and read icon, code and
  English name (`LocaleInfo::display_text`, e.g. "🌐 JA Japanese"),
  so they render without a CJK font. `LocaleInfo::native_name` is not
  shown anywhere.
- Picking a row calls `ensure_font_for_locale` and then
  `i18n::set_locale`; the UI changes on the next frame, with no restart.
- If the locale needs a font that cannot be loaded, the locale is set to
  English instead. The desktop app shows a "Font Required" dialog
  pointing at `assets/fonts/`; the web build logs an error.

**The choice is saved.** The picker calls `i18n::set_locale` and
nothing else; after each frame's UI the app compares the locale with
`SystemSettings.language` (default `"en"`) and, when they differ, writes
it through `ConfigPath::SystemLanguage`, which saves immediately. At
startup `App` applies the saved language, after loading its font; a
locale whose font the platform cannot load stays in English, as the
picker does.

## Fonts

| When | Desktop | Web |
|---|---|---|
| Startup | `initialize_default_fonts` puts `assets/fonts/NotoSans-Regular.otf` first in the proportional family, ahead of egui's defaults (egui's defaults alone if the file is missing) | egui's default fonts |
| Choosing `en`, `es`, `fr`, `de`, `ru`, `pt`, `it`, `pl`, `uk` or `el` | any locale font is removed | the same |
| Choosing `ja` | loads `assets/fonts/NotoSansJP-Regular.otf` | no CJK font: falls back to English |
| Choosing `zh-CN` | loads `assets/fonts/NotoSansSC-Regular.otf` | no CJK font: falls back to English |

- A locale font is inserted first in both the proportional and the
  monospace families (as `custom_<name>`), with the existing fonts
  behind it for any glyph it lacks.
- Font files resolve through `resources::resource_path`: the working
  directory, then beside the executable, then a macOS bundle's
  `Resources`. The shipped fonts are under the SIL Open Font License
  (`assets/fonts/OFL.txt`).
- `get_font_config` also names files for `zh-TW`, `ko`, `ar` and `he`;
  none is shipped and none of those locales exists.

## Tests

In [src/i18n.rs](../../src/i18n.rs):

| Test | Checks |
|---|---|
| `every_key_the_code_uses_has_english_text` | Scans `src/` for literal keys in `t!("...")`, `I18nKey::simple("...")`, `I18nKey::with_params("...")` and `"history.action.*"` strings (skipping comment lines), and fails on any without English text. A missing key would otherwise be drawn as the key itself. Keys built at run time (from a variable or `format!`) are not seen |
| `no_invisible_emoji_modifiers_in_translations` | Fails on U+FE0F, U+FE0E or U+200D in any locale file: egui draws each as a box beside its emoji. Write "⚠", not "⚠️" |
| `test_default_locale`, `test_supported_locales` | English is the default and the first supported locale |

Elsewhere, `visibility::tests::every_reason_resolves_to_real_text` and
`the_window_menu_is_well_formed` check the keys those tables name.

```bash
cargo test --release --lib i18n
```

## Adding a key

1. Add it to `locales/en.yml` under the group it belongs to.
2. Use it: `use rust_i18n::t;` then `t!("group.key")`, or
   `t!("group.key", name = value)` for a `%{name}` parameter.
3. Translating it is optional; a locale without it shows the English.
4. Run the tests above. Keep emoji bare (no U+FE0F).

## Adding a language

1. Create `locales/<code>.yml` starting with `_version: 1` and the same
   key tree as English; leave out what is not translated yet.
2. Add `LocaleInfo::new(code, english_name, native_name, "🌐")` to
   `supported_locales()` in [src/i18n.rs](../../src/i18n.rs). The globe
   menu lists exactly that.
3. Make `ensure_font_for_locale` accept it
   ([src/ui/font_loader.rs](../../src/ui/font_loader.rs)): add the code
   to its list of languages the default font covers, or add a font file
   to `assets/fonts/` and an arm to `get_font_config`. A code in
   neither falls back to English when picked.
4. Rebuild: the locale files are compiled in. A locale that needs its
   own font falls back to English on the web, which loads none.
