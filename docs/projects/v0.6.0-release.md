## The API

Done on the server and merged (2026-11-11/12, the API plan's steps 1-3 and
5: [api-updates.md](../archive/projects/api-updates.md)): the reader parameter (migration 100),
the contract re-pinned with the slot cap at 4096, script kind `library`
and render mode `simulation` (102), effects re-seeded with the Rhai twins'
WGSL (103), the variation corpus re-imported (104), animation motion blur
(105), the catalog (106), transforms up to 64 KB (107). The render-mode
check reads `render_modes.known`; the old `client-sync-2026-10` branch is
gone.

- [ ] **Deploy the server before the app.** An app that uploads a
      simulation to a server without migration 102 gets a 400. The first
      start after migration 106 summarises every stored flame in the
      background.
- [ ] **Scripts: run the regenerated built-in script import by hand on
      the deployment**, after the server's migrations. It is not a
      migration: it names the admin account
      (`31f422c2-e70f-4cd9-a704-85e2f65f044b`) that owns the built-ins, an
      account only the deployment has.

      ```bash
      psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f tools/generated/import_builtin_scripts.sql
      ```

      Regenerated 2026-11-11 from this build's corpus
      (`export_scripts_json`, then `tools/generate_script_import.py
      tools/generated/import_builtin_scripts.sql`): 18 scripts, 9
      generators (Halls) and 9 modifiers (Branches). Two are new (*Escape
      deep dive*, *Simulation Sweep*) and six changed. If a built-in script
      changes before the release, regenerate both the corpus and the file
      first; `tests/script_import.rs` runs the emitted file against a
      scratch owner.
- [ ] **Curated content: deploy, then seed by the sync**
      ([curated-content.md](curated-content.md); ffapi's
      `docs/curated-build.md`). Built 2026-11-18 on both repositories'
      `curated-content` branches, **not merged yet**: merge both first.
      The server goes out before the app. The app's Catalog asks for
      `?curated=true` and resolves names at `/curated/...`, so a server
      without migration 119 answers its Online place with 400s. Its
      Curated lists stay empty until the sync below has run.
      1. **Deploy the server.** Migrations 119-121 run on start. They add
         columns with defaults, two tables (`curated_names`,
         `curated_name_tombstones`) and the static triggers, and replace
         `touch_updated_at`. They rewrite no rows. The first start then
         writes `content_hash` on every variation and effect in the
         background (`backfill_builtin_hashes`). The server needs
         serde_json's `float_roundtrip`, which is in its `Cargo.toml`:
         without it, about 1% of records come back `hash_mismatch`.
      2. **Write the manifest from the release build** (this repository):
         `cargo run --release --bin export_curated_json`, which writes
         `output/curated-manifest.json`. It holds the presets, the palette
         packs, the shipped scripts and Rhai examples, and the variation
         and effect corpora: about 1,550 records, 13 MB.
      3. **Dry run against production** (ffapi), with the admin account's
         token (`31f422c2-e70f-4cd9-a704-85e2f65f044b`; sign in with
         `POST /api/v1/auth/login`):

         ```bash
         FFAPI_TOKEN=... python tools/sync_curated.py ../fractal-art-editor/output/curated-manifest.json \
             --api https://fractalsforall.com --report curated-sync-report.json
         ```

         It writes nothing without `--write`. Read the report:
         - `hash_mismatch`: stop. The two hash definitions disagree.
         - `taken_over`: the hand imports, found by their content.
         - `needs_decision`: a hand import with the same name but other
           content.
         - `gone`: synced names missing from the manifest.
         - `error`: anything else.
      4. **Write it:** the same command with `--write`. Add
         `--accept kind/name,...` for each `needs_decision` to keep as an
         older version. Add `--retire` only to retire what is `gone`: it
         tombstones names and **deletes** built-in variation and effect
         rows. `--kinds` limits a run to some kinds.

      Once the sync has run, it replaces the reseed migrations and the
      hand-run script import above. The built-in scripts come through the
      sync, taken over by hash if they are unchanged. The local dry run
      (2026-11-18) created 84 fractals, 728 palettes and 60 scripts. Every
      variation and effect came back unchanged, with no mismatches.
- [ ] **Re-sync the generated files** if anything they describe changed
      since 2026-11-11: the contract, the catalog
      (`docs/generated/engine-catalog.json`) and the three corpora
      ([RELEASE.md](../RELEASE.md) §3). The API's `catalog_conformance`
      and `contract_conformance` fail on a stale copy.
- [ ] **The update notice reads GitHub** (decided 2026-11-24,
      [release-streamlining.md](release-streamlining.md) §3; built on
      ffapi's branch `app-latest-github`): set `APP_RELEASES_REPO` (the
      app's `owner/name`) in the server's `.env`, and leave
      `APP_LATEST_VERSION` unset, since it overrides GitHub. `/app/latest`
      then answers with the newest GitHub release that is not a draft or
      prerelease, cached for an hour. If the repository is private, also
      set `APP_RELEASES_TOKEN`.
- [ ] **The JS browser app:** its changes for 0.6 are listed in ffapi's
      `docs/BROWSER_APP_0.6.md`, starting with sending `reader=7` on every
      request. Until it does, the server answers it in 0.5's vocabulary
      (no escape-time, no simulations).

Not in this release: publishing and adopting the GPU Rhai kinds online --
effects, variations, formulas, colourings, solids, simulation models,
tracks -- as one scripts resource with a `kind` field (the API plan's step
4, deferred 2026-11-12). Until then a config carries the sources it uses,
and the API stores the WGSL catalogs as it does now.

## Deploy the latest modules

- [ ] **Run the gallery modules' tests** (`python scripts/release.py
      gallery`): their GPU smoke tests and the script module's CLI
      parity.
      **The parity fails (found 2026-11-26):** `FractalConfig::to_json`
      puts `min_reader` after `version` by inserting into a map, which
      keeps that order only with serde_json's `preserve_order`. The
      desktop build gets it through a dependency; the gallery module,
      built without the web app, does not, so its JSON has `min_reader`
      sorted alphabetically: the same content, in a different byte order.
      Turn `preserve_order` on for every build, or order without it.
      Present since `min_reader` (2026-11-11).
- [ ] **Ship together.** The web app (`./build-wasm.sh`, `--profile
      dist`) and both gallery modules (`wasm/render`, `wasm/script`) go
      out with the desktop release; the gallery already loads
      `fae-render`. Saves are config version 7 with `min_reader` 7,
      which builds before 0.6 refuse to open.
- [ ] **Try the web app's custom-size export in a browser** before
      deploying. It now goes through `render()`, and has never been run
      in a page. Cover:
      - a flame with colour effects at a large size;
      - a lit 3D solid;
      - an auto-exposed deep view;
      - an escape picture, an escape terrain and a simulation.
- [x] **Try motion blur in the web app's playback** (the user,
      2026-10-29) -- a flame, an
      escape picture, a simulation with a step track, a terrain -- which
      no browser had run yet.
- [ ] **Gallery speed:** escape chunks are a fixed size on the web now
      (`set_fixed_chunk`), and the renderer's default iterations per
      thread rose from 256 to 1024 (2026-11-04) for a page that names
      none. Check that a gallery of flames and escape configs, all
      through `wasm/render` now, still scrolls well.
