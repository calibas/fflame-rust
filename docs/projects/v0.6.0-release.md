# v0.6.0 release

**Status 2026-11-12:** the feature work is merged; what is left is
testing, bug fixes and UI/UX polish, then the release itself. The
procedure is [docs/RELEASE.md](../RELEASE.md), and the plan to streamline
it ([release-streamlining.md](release-streamlining.md)) is the last item
before the release, tested by the release itself.

## The API

Done on the server and merged (2026-11-11/12, the API plan's steps 1-3 and
5: [api-updates.md](api-updates.md)): the reader parameter (migration 100),
the contract re-pinned with the slot cap at 4096, script kind `library`
and render mode `simulation` (102), effects re-seeded with the Rhai twins'
WGSL (103), the variation corpus re-imported (104), animation motion blur
(105), the catalog (106), transforms up to 64 KB (107). The render-mode
check reads `render_modes.known`; the old `client-sync-2026-10` branch is
gone.

- [ ] **Deploy the server before the app.** An app that uploads a
      simulation to a server without migration 102 gets a 400. The first
      start after migration 106 summarises every stored flame in the
      background.
- [ ] **Scripts: run the regenerated built-in script import by hand on
      the deployment**, after the server's migrations. It is not a
      migration: it names the admin account
      (`31f422c2-e70f-4cd9-a704-85e2f65f044b`) that owns the built-ins, an
      account only the deployment has.

      ```bash
      psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f tools/generated/import_builtin_scripts.sql
      ```

      Regenerated 2026-11-11 from this build's corpus
      (`export_scripts_json`, then `tools/generate_script_import.py
      tools/generated/import_builtin_scripts.sql`): 18 scripts, 9
      generators (Halls) and 9 modifiers (Branches). Two are new (*Escape
      deep dive*, *Simulation Sweep*) and six changed. If a built-in script
      changes before the release, regenerate both the corpus and the file
      first; `tests/script_import.rs` runs the emitted file against a
      scratch owner.
- [ ] **Re-sync the generated files** if anything they describe changed
      since 2026-11-11: the contract, the catalog
      (`docs/generated/engine-catalog.json`) and the three corpora
      ([RELEASE.md](../RELEASE.md) §3). The API's `catalog_conformance`
      and `contract_conformance` fail on a stale copy.
- [ ] **Set `APP_LATEST_VERSION`** (and `APP_LATEST_URL`) on the server
      when 0.6 is published, so older desktop apps from 0.6 on see the
      update notice.
- [ ] **The JS browser app:** its changes for 0.6 are listed in ffapi's
      `docs/BROWSER_APP_0.6.md`, starting with sending `reader=7` on every
      request. Until it does, the server answers it in 0.5's vocabulary
      (no escape-time, no simulations).

Not in this release: publishing and adopting the GPU Rhai kinds online --
effects, variations, formulas, colourings, solids, simulation models,
tracks -- as one scripts resource with a `kind` field (the API plan's step
4, deferred 2026-11-12). Until then a config carries the sources it uses,
and the API stores the WGSL catalogs as it does now.
