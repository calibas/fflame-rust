# v0.6.0 release

**Status 2026-10-12:** tracking only. More changes land before the
release; nothing below is started. The procedure itself is
[docs/RELEASE.md](../RELEASE.md).

## Update the API

The API repository (`ffapi`) last imported in August 2026. Redo every
step from the corpora of the build being released, not from earlier
copies. Updated 2026-11-03 for the `rhai-plugins` branch
([rhai-plugins.md](rhai-plugins.md)); what it changes is marked
*rhai-plugins* below.

- [ ] **Re-pin the engine contract.** Copy
      `docs/generated/engine-contract.json`. Set the API's
      `EXPECTED_SHAPE` (`tests/contract_conformance.rs`) to the release's
      `shape`. It was `23a163e0bf37ffe9` on 2026-10-12 and still is on
      2026-11-03; the API still pins `0441465e249b6911`, two moves back.
- [ ] **Accept the script kind `library`** (*rhai-plugins*, P0). The
      contract's script `kinds` gained it, but a new kind does not move
      the `shape` (RELEASE.md §3), so conformance will not flag it. A
      library -- functions other scripts `import` -- can now be
      published (`script_to_create_request` sends `kind: "library"`), so
      the scripts resource's kind check, its Postgres type and
      `docs/main/openapi.json` need it.
- [ ] **Config version 7** (*rhai-plugins*). Configs saved by this
      release are v7: a Rhai variation is keyed by its id and version
      (`u<uuid hex>_<8 hex>`). Older configs migrate when the client loads
      them, and a flame's carried Rhai sources (`custom_effects`,
      `flame.custom_variations`, the escape block's custom formula and
      colouring, the simulation block's custom model and colouring) ride
      in the opaque config blob, so nothing there changes. Two things to
      check in the API:
      - whether it reads the blob's `version` anywhere;
      - whether it checks a transform's variation names against its
        catalog. A Rhai variation's name is now its key.
- [ ] **Fix the API's render-mode check.**
      `render_mode_enum_covers_every_contract_mode` reads `render_modes`
      as an array, but the contract publishes an object (`known`,
      `wire_path`), so the check has never run. Read `known`.
- [ ] **Decide `simulation`.** `render_modes.known` lists it, but the
      client refuses to upload simulations. Either exclude it in that
      check, or add it to the Postgres `render_mode` enum and
      `docs/main/openapi.json` if simulations are to be stored. Since
      *rhai-plugins* a simulation may run Rhai models and colourings,
      carried as source in its config blob, so storing one needs nothing
      more than the blob.
- [ ] **Variations:** regenerate the corpus (`export_variations_json`),
      copy it, and emit a re-import migration with
      `tools/generate_variation_import.py`, as the API's migration 97
      did. Changed so far: `subflame_wf`, `pre_subflame_wf` (new WGSL,
      nine state slots) and `mondrianomies`. *rhai-plugins* touches no
      built-in variation.
- [ ] **Effects:** regenerate (`export_effects_json`) and emit a re-seed
      migration with `tools/generate_effect_import.py`. So far:
      - `distance_field` is new;
      - 15 shaders now sample with `textureSampleLevel`;
      - `density_blur` has new parameter descriptions and reads the
        uniform's new `density_mean`;
      - *rhai-plugins* (D1): the 15 one-pass built-ins are registered as
        their Rhai twins (`effects::custom::BUILTIN_TWINS`), and the
        exporter reads the registry. Read from the code, not yet run:
        - their `shader` becomes the WGSL each twin compiles to (the
          generated module, not the hand-written file under `shaders/`);
        - their parameters gain `description`s, from the twins' hints,
          for the first time.

        Diff the corpus before re-seeding, and decide which WGSL the API
        should hold until P6 stores the Rhai source: what the app runs
        (the twin's), or the hand-written reference
        (`effects::wgsl_builtins`).

      The API's publish check could reject implicit-derivative sampling
      too (`effects_never_sample_with_implicit_derivatives` is the
      reference).
- [ ] **Scripts:** regenerate (`export_scripts_json`), emit the import
      SQL with `tools/generate_script_import.py`, and run it by hand on
      the deployment. Two scripts are new (*Escape deep dive*,
      *Simulation Sweep*) and six changed. *rhai-plugins* changes no
      built-in script (but see `library` above).
- [ ] **Motion blur** ([motion-blur.md](../archive/projects/motion-blur.md), D6): store an
      animation's `motion_blur` (`enabled`, `shutter`, `samples`) beside
      its loop mode, and have the client send and read it
      (`animation_response_to_animation` sets the default meanwhile), or
      an animation saved online loses it.
- [ ] Run the API's full test suite. It applies migrations to the
      `DATABASE_URL` in its `.env`.
- [ ] Clean up the local `ffapi` branch `client-sync-2026-10`. It holds
      uncommitted copies from 2026-10-12, a start abandoned when that
      session could not work in another repository. Discard it, or
      rebase it on the release's files.

Not in this release: publishing and adopting the GPU Rhai kinds online --
effects, variations, formulas, colourings, solids, simulation models --
as one scripts resource with a `kind` field ([rhai-plugins.md](rhai-plugins.md),
P6). Until then a config carries the sources it uses, and the API stores
the WGSL catalogs as it does now (D2).

## Deploy the latest modules

- [ ] **Ship together.** The web app (`./build-wasm.sh`, `--profile
      dist`) and all five gallery modules (`wasm/render`, `script`,
      `flame`, `escape`, `sim`) go out with the desktop release. Saves
      are config version 7 (version 6 until *rhai-plugins*), which older
      builds refuse to open.
- [ ] **Try the web app's custom-size export in a browser** before
      deploying. It now goes through `render()`, and has never been run
      in a page. Cover:
      - a flame with colour effects at a large size;
      - a lit 3D solid;
      - an auto-exposed deep view;
      - an escape picture, an escape terrain and a simulation.

      2026-10-29) -- a flame, an
      escape picture, a simulation with a step track, a terrain -- which
      no browser has run yet.

      now (`set_fixed_chunk`). Check that the escape gallery module
